# Documentation

## Sections

- **[architecture/](./architecture/)** — system design, database schema, multi-tenancy, real-time
- **[api/](./api/)** — OpenAPI spec (auto-generated), API changelog
- **[adr/](./adr/)** — Architecture Decision Records (why we chose X over Y)
- **[runbooks/](./runbooks/)** — incident response, deploy, backup/restore procedures
- **[onboarding/](./onboarding/)** — new developer setup
- **[guides/](./guides/)** — how-to: add module, translate, integrate payment

## Document types

- **ADR** (Architecture Decision Record): captures one decision with context + consequences.
  Use when the decision affects architecture, stack, or process.
- **Runbook**: step-by-step procedure for an operational scenario.
- **Guide**: tutorial for common development tasks.
- **Reference**: API spec, schema diagrams, configuration tables.

## Writing style

- Short headers, scannable
- Concrete examples > abstract principles
- Code blocks where possible
- Link to source, don't duplicate

## Living docs

- `api/openapi.yml` — auto-generated by Scribe, commit changes
- Architecture diagrams — source in Mermaid (`.mmd`), render on demand
- ADRs — immutable once accepted, superseded by new ADR (don't edit history)
